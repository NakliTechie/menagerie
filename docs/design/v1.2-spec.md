# Menagerie v1.2 — "It's a tree" — build spec

> **Lock-and-fold gate.** This is the spec the v1.2 build runs off, the way v1.1
> ran off `HANDOFF-v1.0.md` + the §7 UX reference. No tree code lands until this
> and [`v1.2-ux-reference.md`](v1.2-ux-reference.md) are locked. Where the doc and
> the repo disagree during build, the repo wins — record the divergence in `STATE.md`.

## 1. What v1.2 is

The deferred supervisor-tree surface: a session can **spawn child sessions**, and
Menagerie shows the parent→children relationship as a **collapsible tree**, with
**subtree operations** (collapse, kill-subtree). The structured transport (v1.1)
is the load-bearing feature; the tree is the research surface — so v1.2 ships the
*smallest tree that is genuinely useful* and defers the speculative parts.

**Success bar (from `DEFERRED.md`):** one supervisor session spawns 4 worker
children; all five are visible as one collapsible tree; killing the supervisor
kills the subtree.

### In scope (v1.2.0)
1. **Parent-child linkage** — a session spawned *by* another session records its
   parent; the relay reports it.
2. **Tree view** — a toggle between the current flat grid and a tree that nests
   children under their parent (sidebar tree + grid grouping).
3. **Subtree kill** — killing a parent offers to kill its whole subtree.
4. **Re-attach rebuilds the tree** — parentage survives a refresh / relay restart.

### Deferred to a later v1.2.x (out of this spec)
- **Agent-to-agent coordination layer** — `wait`, atomic prompt+wait, agent self-
  reported status. The tree (v1.2.0) makes parentage *visible*; the coordination
  layer makes a supervisor *act on* it. Specced in §8 so the v1.2.0 protocol doesn't
  paint it into a corner; built after the tree UI lands. **Directly informed by herdr**
  (`herdr.dev/docs/socket-api`, 32.8K★) — see the capture `[[2026-03-27-herdr]]`.
- **Cross-relay child-spawn** — a child on a *different* relay than its parent.
  Needs a parentage reference that spans relays; the WS/token model is per-relay.
  Design it once single-relay trees are real.
- **Multi-workspace tabs** — independent of the tree research; its own spec.
- **Tiny agent-client lib** — "the protocol is the SDK" holds for v1.2; a wrapper
  only if a supervisor-agent author asks.

### The parentage model (the load-bearing decision — D-v1.2-1)
**A child is a menagerie session spawned with a declared parent — not an OS
subprocess the relay infers.** A supervisor spawns a child by sending a `spawn`
frame carrying `parent_session_id`; the relay records parentage and emits
`child_spawned`. Rationale: explicit, reconstructable on re-attach, and forward-
compatible with cross-relay trees; process-tree sniffing is fragile, doesn't cross
relays, and a child spawned out-of-band isn't a menagerie session anyway (no tile,
no stream). This matches the existing `child_spawned`/`child_session_id` seam and
the "protocol is the SDK" stance (§16) — a supervisor agent (orchestrator) drives
child spawns over the same WS it's streamed on.

## 2. Protocol delta (→ 1.3, additive per §8)

Bump `PROTOCOL_VERSION` `1.2` → `1.3` in **both** `protocol/types.ts` and
`relay-go/internal/protocol/messages.go` (D4 precedent: an added field is a minor
bump). All fields optional; a 1.2 client/relay ignores them and sees a flat grid.

- **`Spawn`** gains `parent_session_id?: string`. When set, the relay verifies the
  parent is a live session owned by the same registration and records parentage.
  An unknown/dead parent → spawn proceeds as a root session (log a warning) — never
  fail a spawn over a stale parent.
- **`Spawned`** echoes `parent_session_id?: string` so the client links the new tile
  immediately (not only via the event).
- **`Event{child_spawned}`** (already defined) is emitted to the **parent's** owner
  when a child spawns: `{session_id: <parent>, event: "child_spawned",
  child_session_id: <child>}`. The child ALSO surfaces as a normal `spawned`/session
  to its own owner (usually the same connection).
- **`SessionInfo`** (the re-attach descriptor) gains `parent_session_id?: string` so
  a refresh reconstructs the tree. (v1.1 already added `transport` here — same shape.)
- **`hello.hosts_children`** becomes `true` (was hardcoded `false`). A client only
  offers "spawn child" / tree affordances against a relay that advertises `true`.
- **Subtree kill** — extend `Signal`: `{type:"signal", signal:"kill", subtree?:true}`.
  With `subtree:true` the relay kills the session and every descendant (depth-first,
  children before parents), emitting an `exited` per session. No new frame type.

### Invariants
- Parentage is a **DAG-free tree**: reject a `parent_session_id` that would create a
  cycle (a session can't be its own ancestor). O(depth) walk on spawn.
- A child's lifecycle is independent unless subtree-killed: a parent exiting does
  **not** auto-kill children (a supervisor can hand off long-running workers) — the
  UI *offers* subtree kill, never forces it.
- Re-attach: the relay reports `parent_session_id` in `listSessions`; the client
  rebuilds the tree from those, tolerant of a parent that's already exited (orphan →
  promoted to root, shown with a "parent exited" marker).

## 3. Relay changes (`relay-go`)

- `sessionEntry` gains `parent string` (guarded by `s.mu`, like the rest of the map).
- `handleSpawn`/`handleSpawnACP`: read `msg.ParentSessionID`; validate (live, same
  registration, no cycle) under `s.mu`; store on the entry; echo in `Spawned`; queue
  a `child_spawned` Event to the parent.
- `listSessions`: include `parent_session_id`.
- Subtree kill: a `killSubtree(id)` that snapshots descendants under `s.mu` (a
  parent→children index or a scan of entries by `parent`), then kills leaf-first.
  Reuse the existing per-session kill; each still emits `exited`.
- `child_spawned` rides the **same outbox/trySend funnel** as every other frame
  (Batch A's closed-guard applies) — never a raw `e.outbox <-`.
- `hosts_children = true` in the hello builder.

## 4. Browser changes (`index.html`)

- **Session model:** each session record gains `parentId` (from `spawned`/`SessionInfo`).
  A derived `childrenOf(id)` index, rebuilt on session add/remove.
- **Tree view toggle** (topbar, next to the sidebar toggle): flat grid ⇄ tree. Persist
  the choice (localStorage) like the theme.
- **Sidebar tree:** sessions render as a collapsible tree (parent with a disclosure
  triangle, children indented). Collapse state per-parent, persisted.
- **Grid grouping (tree view on):** children render grouped under their parent (an
  indented band or a bounding group), not scattered in spawn order.
- **Spawn-child affordance:** on a tile whose relay `hosts_children`, a "spawn child"
  action pre-fills the spawn dialog with `parent_session_id`.
- **Subtree kill:** the tile/parent kill control, when the session has children, asks
  (in-app modal — NOT `confirm()`, per the no-native-dialogs rule) "kill this session
  and its N children?" → sends `signal{kill, subtree:true}`.
- **Re-attach:** rebuild `parentId` from `SessionInfo.parent_session_id`; render the
  tree; orphaned children (parent gone) show a "parent exited" chip and sit at root.
- All new agent/relay-controlled strings through `escapeHtml` (H1 discipline).

## 8. Coordination layer (v1.2.x — specced now, built after the tree UI)

The tree makes parentage *visible*; coordination lets a supervisor session **act on**
it — spawn a worker, then *park until it genuinely needs you*, without polling. Ported
from herdr's socket API (`herdr.dev/docs/socket-api`, capture `[[2026-03-27-herdr]]`),
mapped onto Menagerie's model: **an agent is just another WS client** (§16, "the protocol
is the SDK"), so coordination is new *frames*, not a side-channel. Nothing here is
needed for v1.2.0 — it's specced now only so the 1.3 frames don't box it in.

### 8.1 The `wait` frame (the load-bearing primitive)
`{type:"wait", session_id, session_token, until, timeout_ms?}` where `until ∈
{needs_input, idle, exited}` (Menagerie's existing status vocabulary — not new states).
The relay resolves it **event-driven** against the target session's next matching
status transition (it already emits `needs_input`/`idle`/`exited` events), replying
`{type:"waited", session_id, state, timed_out}`. Semantics ported verbatim from herdr's
`agent.wait`:
- **Server-owned + event-driven** — no client polling; the relay resolves on the
  transition it already tracks. Reuses the status machinery, not a new watcher.
- **Occupant-pinning** — pin the resolved session by `session_id`; a re-attach keeps
  the same id, but a *different* session reusing a slot must not satisfy a stale wait.
  (Menagerie ids are stable + tokened, so this is lighter than herdr's pane-occupant
  race, but the invariant holds: a wait resolves only for the session it named.)
- **Timeout** — `timeout_ms` bounds it; on expiry reply `timed_out:true`. No infinite
  server-side waits (the C1 concurrency lessons apply — a waiter must never leak;
  resolve-or-timeout, drain on session exit like the pending-request fix).

### 8.2 Atomic prompt+wait
`prompt` gains an optional `wait?: {until, timeout_ms}`: submit the prompt **and** arm
the wait in one frame, so a supervisor can't miss a transition that happens between a
separate prompt and wait (herdr's stated race). The relay arms the wait before
dispatching the prompt.

### 8.3 Agent self-reported status (`report_status`)
`{type:"report_status", session_id, session_token, state, message?}` where `state ∈
{working, needs_input, idle, done}`. Today Menagerie *derives* status (PTY heuristics
+ ACP events); a self-report lets an agent **declare** its state authoritatively — more
reliable than the `LooksLike*` heuristics (whose false-positives the last forward pass
flagged, L5). Display-only metadata (title, token counts) stays separate and never
drives a `wait` resolution (herdr's `report_metadata` vs `report_agent` split).

### 8.4 Events already covered
herdr's `events.subscribe` is largely free here: a supervisor **agent-client** already
receives every session's `event` frames over its WS (the protocol is the SDK). A
per-session/per-state *filter* is a nicety, not a new capability — defer unless a
supervisor author asks.

### 8.5 What this unlocks (the herdr workflow, on Menagerie's rails)
Supervisor spawns N workers (`spawn{parent_session_id}`, v1.2.0) → `prompt{wait:{until:
"needs_input"}}` each → parks until a worker is genuinely blocked → answers it → repeats;
subtree-kill (v1.2.0) tears the whole thing down. The tree UI *shows* it; §8 lets an
agent *drive* it headless.

## Decisions log (this build)
- **D-v1.2-1 — parentage is protocol-declared, not process-inferred** (§1). A child is
  a menagerie session spawned with `parent_session_id`; the relay never sniffs the OS
  process tree.
- **D-v1.2-2 — coordination is WS frames, not a side-channel** (§8). `wait` / atomic
  prompt+wait / `report_status` are first-class protocol frames a supervisor agent-client
  sends over the same connection it's streamed on — herdr's socket-API model, mapped onto
  "the protocol is the SDK." Specced as v1.2.x; the 1.3 shapes leave room for it.
