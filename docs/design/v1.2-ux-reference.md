# Menagerie v1.2 — Tree UX reference

> **Gate document (spec §5).** C3+ (any browser tree code) do not open until this
> exists and is locked. It fixes every new surface, its states, and the tokens it
> uses — before any code. Edit here first if the design moves during the build.
> Sibling of [`v1.1-ux-reference.md`](v1.1-ux-reference.md); same discipline.

## Unity sentence

> **The fleet is a forest — supervisors and their workers read as one shape you can
> collapse, follow, and stop as a unit, without losing the flat board when you want it.**

Not a file explorer, not an org chart. The tree is *the same tiles and sidebar rows*
as v1.1, only nested by who-spawned-whom. Density and legibility over decoration; the
flat grid stays one toggle away. No new color, no new type family — the existing
Rangrez ramp, reused.

## Tokens

| Meaning | Token |
|---|---|
| Tree lines / indent guides | `--border` (1px), 16px indent per depth |
| Disclosure triangle | `--muted`, rotates 90° open |
| Parent (has children) row accent | `--text` name, child-count pill in `--faint` |
| Child row | one indent step, `--muted` connector |
| Orphan ("parent exited") chip | `--yellow` inline strip (same as backpressure) |
| Subtree-kill danger | `--red` (the modal's confirm button) |
| Group band (grid, tree view) | `--panel-2` hairline left border in `--border` |

## 1. Tree view toggle (topbar)

A segmented toggle beside the ☰ sidebar toggle: **▦ Grid** · **⇊ Tree**. Persisted
(localStorage, like theme). Default **Grid** — a first-time / no-children fleet never
sees tree chrome. Tree only becomes meaningful once a session `hosts_children`.

```
┌ topbar ───────────────────────────────────────────────┐
│ ☰  Menagerie.  ~/code            ▦ ⇊    + Spawn  ? ◐ ⚙ │
└────────────────────────────────────────────────────────┘
```

## 2. Sidebar tree (the primary surface)

Sessions render as a collapsible tree. A parent shows a disclosure triangle + a
child-count pill; children indent one step under it with a connector.

```
SESSIONS
  ▾ ● orchestrator          localhost   ⑃4     ← parent: triangle + child-count pill
      ● worker · auth        localhost
      ● worker · api         localhost
      ◐ worker · tests       localhost         ← needs-input dot, unchanged
      ✓ worker · docs        localhost
  ● lint-run                 localhost         ← a root session with no children (flat)
```

- **Collapse/expand:** click the triangle (or `←`/`→` on a focused parent). Collapsed
  parent shows a rolled-up status (`⑃4 · 1 needs you`). Collapse state per-parent,
  persisted.
- Child rows carry the same status dot / needs-input chime / rate-limit pill as any
  session — nesting changes position, not the row's own vocabulary.
- Depth is capped visually at ~4 indents; deeper nests keep indenting text but clamp
  the guide rail (don't march off the panel — reuse the toolbar-overflow discipline).

## 3. Grid grouping (tree view ON)

In **Tree** view the grid groups a parent's children beneath it under a light band;
in **Grid** view (default) tiles stay flat in spawn order (v1.1 behavior, untouched).

```
┌ orchestrator ─────────────┐
│ ● localhost · 02:14   ⛶ ⤢ │   ← the parent tile, normal
└───────────────────────────┘
 │  ┌ worker · auth ───────┐ ┌ worker · api ────────┐   ← children: left band in --border,
 │  │ ● …                  │ │ ● …                  │     one indent, same tile chrome
 │  └──────────────────────┘ └──────────────────────┘
```

- The band is a hairline left border (`--border`) + faint `--panel-2` wash on the
  group, NOT a box around each child (density).
- Collapsing the parent in the sidebar also collapses its grid group (single source
  of collapse truth per parent).

## 4. Spawn a child

On a tile whose relay advertises `hosts_children`, the tile actions gain a **⑃ spawn
child**. It opens the normal spawn dialog **pre-filled** with `parent_session_id` (a
read-only "child of: orchestrator" chip at the top), cwd inherited from the parent,
agent blank (spec Q2). Relays without `hosts_children`: the action is absent (not
disabled) — never offer what the relay can't do.

```
┌ New task ─────────────────────────────────┐
│ child of: ● orchestrator   (parent)        │   ← read-only chip; removing it = root spawn
│ Task  [ …                              ]   │
│ Agent [ ▾ ]   Model [ ▾ ]   cwd ~/code/api │
└────────────────────────────────────────────┘
```

## 5. Subtree kill (in-app modal — never `confirm()`)

Killing a session that has children asks first, in an in-app modal (the no-native-
dialogs rule), and states the blast radius:

```
┌ Kill subtree? ────────────────────────────┐
│ orchestrator has 4 children.               │
│ ○ Kill only orchestrator (children keep    │
│    running, promoted to root)              │
│ ● Kill orchestrator and all 4 children     │   ← default; red confirm
│                                            │
│         [ Cancel ]      [ Kill 5 ]         │
└────────────────────────────────────────────┘
```

- Killing only the parent **orphans** the children (they survive — a supervisor can
  hand off workers, spec invariant). Killing the subtree sends `signal{kill,
  subtree:true}`; each session gets its own `exited` and dims leaf-first.
- A childless session's kill is unchanged (no modal).

## 6. Empty / orphan / error states

| State | Shows |
|---|---|
| Relay without `hosts_children` | no tree toggle, no spawn-child — pure v1.1 |
| Parent exited, children live | children promoted to root, each with a `--yellow` `⤺ parent exited` chip |
| child_spawned for an unknown parent | child shown at root (never dropped); logged |
| Cycle attempted (relay-rejected) | spawn returns an error toast: "would create a loop" |
| Deep nest (>4) | indent text clamps; rail stops; count pill still accurate |

## 7. Keyboard additions (checked against the v1.0/v1.1 table)

| Key | Context | Action |
|---|---|---|
| `t` | anywhere (no modal/input) | toggle Grid ⇄ Tree |
| `←` | focused parent row/tile | collapse subtree |
| `→` | focused collapsed parent | expand subtree |
| `c` | focused tile, relay hosts children | spawn child (opens dialog) |
| `Enter`/`f`/`Tab`/`Esc` | unchanged | as v1.1 |

Added to the hotkey table in the same commit as the implementation; the tour gains
no step in v1.2.0 (tree is discoverable via the toggle; revisit if usage says otherwise).
